# DOM 树 / 工作区面板空间优化方案

> 背景：右侧「DOM 树」与「工作区版本」原本是**并排**的固定宽面板，合计 572px（272 + 300）。典型侧栏宽约 598px 时，页面被压缩到约 26px，「两个面板一开，页面就没了」。
> **状态：已按「A + C 自适应 + D」实现**（2026-11-10）。实现落在 `src/client/domains/inspector/dock.tsx`、`body.tsx`、`dom-tree.tsx`、`git-panel.tsx`，测试见 `test/dock-panel.test.mjs`、`test/workspace-panel.test.mjs`。

## 1. 现状诊断

| 观察 | 数值 / 行为 |
| --- | --- |
| DOM 树面板宽度 | 固定 `272px`（`dom-tree.tsx` `width/minWidth: 272`） |
| 工作区面板宽度 | 固定 `300px`（`git-panel.tsx` `width/minWidth: 300`） |
| 两个同时打开 | 572px，页面 webview 被挤到几乎为 0 |
| 打开/关闭 | 两个独立布尔状态，可同时为 true；工具栏两个按钮各自开合 |
| 宽度能力 | 不可拖拽、不记忆、无自适应；窄侧栏无降级 |
| 头部开销 | 两个面板各有一套 header（标题 + 关闭，工作区还有刷新），再加 repo 警告行 + 内置 tabs |
| 空状态开销 | 未检测到 git 时，仍展示「版本 / 提交」tab 与常驻警告行 |

根因不在「面板太宽」，而在于**面板参与横向 flex 布局且允许并排**：页面不是被面板盖住，而是被真实挤压。

## 2. 设计目标

1. 任何侧栏宽度下，页面都保留可用的可视宽度（建议 ≥ 260px，或完全不被压缩）。
2. 同一时刻不出现「DOM + 工作区」并排挤死页面。
3. 面板宽度可调、可记忆，窄侧栏有降级形态。
4. 面板内部信息密度提高，空状态不占常驻高度。
5. 不改面板的内容能力（DOM 选择、文件/版本/提交、热更新回写）。

## 3. 方案对比

| 方案 | 做法 | 占用 | 改动量 | 取舍 |
| --- | --- | --- | --- | --- |
| **A. 单 Dock + 顶层 Tab（推荐）** | 两个面板合并成一个右侧 Dock，顶部一级 Tab「DOM 树 / 工作区」，同一时刻只渲染一个；Dock 宽 300，可拖 240–420，双击复位并记忆 | 300px（页宽 ≈ 298） | 中（约 1–1.5 天） | 最多一个面板，无法同屏对照两个面板 |
| **B. 互斥 + 自适应宽（最小止血）** | 打开一个自动关闭另一个；宽度 `clamp(220, 36%, 360)`；加拖拽把手与宽度记忆 | 220–360px | 小（约 0.5 天） | 仍是两个独立面板，头部重复、不能同屏 |
| **C. 浮层抽屉** | 面板 `position:absolute` 浮在页面右侧，页面保持全宽；带阴影、Esc / 点空白关闭 | 覆盖 320px，页面不缩 | 中（约 0.5–1 天，可与 A 叠加） | 会遮住部分页面，适合窄侧栏 / 临时查看 |
| **D. 面板内部瘦身** | 行高 24→22、缩进 12→10、header 36→32；无 git 时隐藏「版本 / 提交」tab 并合并警告行；文件路径 hover 才显示完整 | 面板内节省 20–30px 高、~40px 宽 | 小–中（约 0.5–1 天） | 纯收益，可与 A/B/C 任意组合 |

## 4. 推荐路线

**A + D 为主，C 作为窄侧栏自适应降级。**

- 侧栏宽度 ≥ 760px：Dock 停靠，占 300px（可拖宽），页面保留剩余宽度。
- 侧栏宽度 < 760px：Dock 自动切换为浮层抽屉（C），页面保持全宽，Esc / 点空白 / 再点工具栏按钮关闭。
- 无论哪种形态，同一时刻只有一个面板内容可见。

如果只想先止血：**B + D**，半天内可上线，之后再演进到 A + C。

### 4.1 形态与交互

```
┌──────────────────────────────┬─────────────┐
│                              │ DOM 树 | 工作区 │  ← 一级 Tab
│        页面 webview           ├─────────────┤
│                              │ 面板内容      │
│                              │             │
└──────────────────────────────┴─────────────┘
        ↑ 可拖拽分隔线（240–420px，双击 300）
```

- 工具栏「DOM 树 / 工作区版本」按钮 → 打开 Dock 并选中对应 Tab；再点同一按钮关闭 Dock；点另一个按钮只切 Tab，不再叠加面板。
- Dock 顶栏：一级 Tab + 右侧关闭（×）；一级 Tab 内保留工作区自己的「文件 / 版本 / 提交」二级 Tab。
- 拖拽：分隔线 4px 命中区，`cursor: col-resize`，拖动时实时改宽，松手写 `localStorage`（按 tab 或全局记忆）；双击复位 300；键盘左右键可调宽（步进 16）。
- 浮层形态：`absolute inset-block: 0; right: 0; width: 320px`，带左阴影；`Esc` 关闭；焦点回到工具栏按钮；点面板外空白关闭（可选，默认开启）。
- 面板打开状态与宽度按会话/tab 记忆；切换会话不串状态。

### 4.2 配套瘦身（D）

**DOM 树**
- header 高 36 → 32；节点行高 24 → 22，缩进 12 → 10。
- header 右侧的关闭按钮在 Dock 形态下隐藏（关闭交给 Dock）；保留刷新 / 折叠能力。
- 节点名称超宽截断 + `title`，避免长 class 名撑宽。

**工作区**
- 无 git（`gitUnavailable`）时：隐藏「版本 / 提交」二级 Tab，只保留「文件」；把「没有检测到 git 仓库」从常驻警告行收成文件列表顶部的一行浅色说明。
- repo 状态（干净 / 有改动 / 游离 HEAD）收成 header 内的小 chip，不再单独占一行。
- 文件右侧的目录路径改为 hover 显示或截断，默认只显示文件名 + 图标。
- 打开文件后的「来源 / 预览」提示合并到文件行内联状态，不额外占行。

## 5.1 实现记录（与方案的差异）

- Dock 默认宽 300，拖拽范围 240–420，双击 / Home 复位；宽度写 `localStorage['dsh.nudge.dockWidth']`。
- 停靠 / 浮层阈值取 **760px**；浮层宽 `clamp(240, 320, 宿主宽 - 96)`，保留至少 96px 页面可见；浮层只支持 Esc、Dock 关闭按钮和工具栏按钮关闭（未做「点外部关闭」，避免误关）。
- 拖动分隔线时渲染全屏 `data-dockkit-pointer` 捕获层，避免指针经过 `<webview>` 时宿主 document 收不到 mousemove。
- 工作区无 git：二级 Tab 整条隐藏（只剩「文件」时不再画 tab 条），仓库提示收进文件列表首行；文件父目录默认 `display:none`，hover / focus 才显示。
- DOM 树行高 / 缩进原本已是 22px / 12px，本轮只做嵌入化（去固定宽、去自带头部/关闭）。

## 6. 验收标准

- 598px 侧栏：只开一个面板时页面可视宽度 ≥ 260px；两个入口轮流点击不再出现并排挤压。
- 宽度拖到 240 / 420 时布局不破；双击 / 键盘可复位；刷新后记住上次宽度。
- 侧栏 < 760px 时自动浮动；Esc、点外部、再点工具栏按钮均可关闭；焦点回到触发按钮。
- 无 git 工作区默认只看到「文件」，没有常驻警告行；文件路径不再默认占宽。
- 面板内容能力不回退：DOM 选中/定位、文件打开、版本列表、提交、热更新回写照旧。
- Light / Dark、`prefers-reduced-motion` 下无跳变。
